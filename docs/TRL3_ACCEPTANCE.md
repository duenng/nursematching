# TRL 3 驗收對照：電郵＋FPS

這是測試對照，不是認證結果。所有資料虛構；「程式測試」使用 mock／FPS 虛構銀行紀錄及注入／虛擬時鐘。Gmail 實際收件及自然時間實驗另列待執行。附件 Stripe 測試步驟依使用者更新改為 FPS。

登入附加驗證：OAuth state／PKCE／nonce、token 驗簽、到期、名單、CSRF、角色限制、臨床資料投影、登出及獨立執行人紀錄由 `auth*.test.mjs` 驗證；真實 Google 雙帳戶登入待記錄。家屬 `/#enquire` 不需登入、提交不回傳連結或其他個案資料。

自動測試入口：`npm run test:workflow`（引擎＋HTTP＋FPS）、`npm test`（完整瀏覽器 FPS 套餐及原有流程）、`npm run build`。測試結果以執行輸出為準。

必須補齊的實驗文件：研究問題／預期、測試配置版本及政策值、執行人與角色、起止時間、虛構資料集、實際結果與失敗、截圖／事件匯出、人工覆核及限制。驗證台「驗收清單」可逐項追加，禁止倒填未觀察結果。

目前不需要 Stripe；以 FPS 人手對數驗證付款關卡，不得把它描述成已驗證 Stripe 或自動銀行入帳辨識。銀行核對是真實服務中的人手職責；TRL 3 先以虛構銀行紀錄演練。
