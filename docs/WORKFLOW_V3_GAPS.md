# v3 MD 對照：目前狀態及差距

核對日期：2026-10-30（香港時間）。對象為使用者提供的 `11platform_workflow_spec_v3_email.md`；已確認與 `docs/reference/workflow-v3-email-draft.md` 完全相同。付款路線按最新決定使用一般銀行轉帳：客人自行轉帳，同事獨立核對銀行入帳；沒有 FPS 或 Stripe 接駁。本頁只記錄程式對照及仍需外部執行的證據，不宣稱 TRL 已認證。

現有主要流程、角色限制及銀行轉帳閘門已建立。`npm run test:workflow` 現時 46／46 通過，`npm test` 現時 24／24 通過；測試使用隔離資料及虛構資料，不能取代 Gmail、Google 雙帳戶、真實銀行入帳或自然 24 小時實驗。

## 付款路線後續更新

使用者確認未有 FPS，改為一般人手銀行轉帳。已新增 `bank_transfer` 模式、銀行資料設定、收款資料未齊阻擋、客人提交後管理員獨立核對及人手退款紀錄；`.env` 已選用該模式。銀行資料仍空白、運行中服務未重啟，未有真實付款／退款驗收。以下原審核結果保留作當時快照，付款模式缺項已有這項程式更新，其餘差距仍待完成。

## 功能有程式，但尚未啟用／實測

- **Gmail SMTP**：本機沒有 `.env`。尚未用團隊帳戶實際寄收 T1、T3、T11、提醒及重新配對通知；連結掃描、失敗處理及遠端連結可達性待驗證。寄失敗目前顯示狀態，沒有完整人工重寄工作流。
- **Google 職員登入**：程式、角色限制、cookie／CSRF 及測試已做；OAuth client、兩類職員名單尚未設定，真實 Google 雙帳戶登入／登出及分權試用未完成。這是後續新增需求，非原 MD 的缺項。
- **銀行轉帳實際操作路線**：`PAYMENT_MODE=bank_transfer` 已建立；客人提交轉帳資料仍是 `PENDING_PAY`，只有管理員獨立核對銀行參考、金額及時間後才可轉 `PAID`／派單。程式未連接銀行 API，亦未執行真實入帳或退款證據。
- **部署與持續運行**：未在本次工作部署或驗證 HTTPS、正式 BASE_URL、持久磁碟、持續 worker、備份還原及遠端寄信。SQLite 單程序與 MD 的 Sheets／Supabase 選項不同；功能可用不等於逐表 schema 已落實。
- **完整偏遠名單**：附件 B 只有外部來源路徑，該檔未提供；只支援名單匯入及人手核對，長洲為明示 C12 fixture。未匯入正式版本前，不能聲稱完整自動分類。

## TRL 證據未完成

MD §14 要求的 F05／F08 加速及最少一次自然經過 24h 實驗，尚沒有外部收件／前後時間證據。另需實際資深護士及 Yi 覆核、各驗收結果、截圖、設定版本、執行人簽署及失敗記錄。自動測試及虛擬時鐘不替代這些證據。此紀錄不宣告 TRL 達標。

## 不應算作本期遺漏

- **舊 FPS／Stripe 路線**：只保留回歸測試及未來 adapter；不屬目前部署付款模式，不能用其測試結果代替銀行轉帳驗收。
- **多次上門、日夜連續、套餐夜間／假期補差價**：MD 本身把未定計價轉 MANUAL。目前未提供完整多日期輸入及組合記錄；這是表格覆蓋差距，但未自動計價符合 MD 的保守原則。
- **待確認商業／臨床規則**：<24h 取消費、護士時薪／假期份額、傷口／PEG 分類、身高門檻、完成方式、套餐適用／有效期等，不能由開發自行定案。已有部分政策開關；尚非正式政策。
- **MD §15.3 明確延後**：WhatsApp API、SMS、正式改期 credit、遲到判定、自動解析電郵、護士入職全流程／註冊到期提醒。真收退款原本亦屬公司註冊後。

下一步：由團隊填妥銀行資料及 Gmail／Google 設定，在隔離部署執行外部收件、雙角色登入、銀行核對、自然 24 小時逾時／無人接單及資深護士／管理員覆核，逐項保存截圖、時間、執行人及失敗紀錄。
